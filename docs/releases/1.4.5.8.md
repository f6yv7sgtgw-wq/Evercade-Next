# Evercade Next 1.4.5.8

## Purpose

This release adds protective pacing and automatic recovery for long-running full-search jobs against GenericParser 0.45.2 Build 6. The GenericParser search runtime itself is unchanged.

## Full-search pacing

- Keep the existing 1500 ms delay between cartridges.
- After every 10 processed cartridges, pause for 30 seconds before continuing.
- Log batch-pause start and end including configured and actual delay.

## Automatic recovery

If a queue item fails and its combined fallback error contains three `Load failed` results, Evercade treats this as three consecutive failed Worker requests and enters recovery mode.

Recovery sequence:

1. Log `queue.recovery.triggered`.
2. Pause for 60 seconds.
3. Call the GenericParser `/health` endpoint from the same browser origin and with the normal module-contract/request-id headers.
4. Resume only after a successful health response.
5. If health still fails, wait 15 seconds and probe again until the Worker is healthy or the user pauses/stops the queue.
6. Reset the consecutive Load-failure counter after successful recovery.

## Diagnostic events

- `queue.batch.pause.start`
- `queue.batch.pause.end`
- `queue.recovery.triggered`
- `queue.recovery.pause.start`
- `queue.recovery.pause.end`
- `queue.recovery.health`
- `queue.recovery.wait`
- `queue.recovery.complete`

## Constants

- Inter-cartridge delay: 1500 ms
- Batch size: 10 cartridges
- Batch pause: 30000 ms
- Recovery threshold: 3 consecutive `Load failed` requests
- Initial recovery pause: 60000 ms
- Failed health-probe retry interval: 15000 ms

## Unchanged

- GenericParser: 0.45.2 Build 6
- Module contract: `generic-parser-module-v1`
- Search source and ranking behavior
- Catalog size and collection data model
