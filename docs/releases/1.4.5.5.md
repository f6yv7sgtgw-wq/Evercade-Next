# Evercade Next 1.4.5.5

Status: stable
Release date: 2026-08-07
Phase: 5.2

## Integration

Evercade Next 1.4.5.5 integrates GenericParser 0.45.2 Build 6 (`gp-0452-20260807-6`) using the unchanged `generic-parser-module-v1` contract.

## Changes

- Targets GenericParser 0.45.2 Build 6.
- Keeps the Worker-edge CORS/preflight fix introduced in GenericParser Build 5.
- Uses GenericParser Build 6 Evercade flat-payload compatibility on `/api/module/search`.
- Keeps `/api/module/v1/search` strict and canonical.
- Corrects Evercade diagnostics: a successfully readable Fetch response with `response.type === "cors"` or `"basic"` is considered browser-accessible even when CORS response headers are not exposed through `response.headers`.
- Retains the 1.4.5.4 differential browser transport probes for regression diagnosis.
- Keeps the existing full-search queue, wishlist-first ordering, pause/resume/reset behavior and persistent progress.
- Keeps version-aware JavaScript asset loading and `VERSION.json` as the canonical release source.

## Proven diagnostic basis

The 1.4.5.4 browser diagnostics demonstrated that GenericParser Build 6 is reachable from the Evercade GitHub Pages origin and reports version 0.45.2, Build 6, the expected module contract and Evercade alias compatibility. The remaining red endpoint indications were caused by the diagnostic logic requiring visible `Access-Control-Allow-*` headers after a response had already been accepted and exposed by the browser.

## Expected validation

The release validator now requires:

- Evercade Next version 1.4.5.5
- stable channel and phase 5.2
- GenericParser 0.45.2 Build 6
- `generic-parser-module-v1`
- browser-readable endpoint-test logic based on Fetch response type
- all existing transport diagnostics
- 87 catalog entries
- full-search queue integrity
- canonical release loader/cache busting

## Non-goals

This release does not add new search sources, multi-source orchestration, ranking changes or price scoring changes.
